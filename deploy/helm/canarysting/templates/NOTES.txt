   kubectl -n {{ .Release.Namespace }} get ds {{ include "canarysting.fullname" . }}-node-agent

   kubectl -n {{ .Release.Namespace }} logs ds/{{ include "canarysting.fullname" . }}-node-agent -c engine
   kubectl -n {{ .Release.Namespace }} logs ds/{{ include "canarysting.fullname" . }}-node-agent -c adapter

   Node preconditions (per node) — the agent will fail to attach without them:
     - cgroup v2 unified hierarchy mounted at {{ .Values.nodeAgent.hostMounts.cgroup.hostPath }}
     - BTF present at {{ .Values.nodeAgent.hostMounts.btf.hostPath }}/vmlinux
     - kernel >= 5.10 (system-global socket cookie; the engine pins a minimum at startup)
{{- if not .Values.nodeAgent.privileged }}
     - the container runtime honors added capabilities: {{ join ", " .Values.nodeAgent.capabilities }}
       (if attach fails with EPERM, set --set nodeAgent.privileged=true)

4) Apply a sample DeceptionPolicy and watch the operator accept it:
   cat <<'EOF' | kubectl apply -f -
   apiVersion: deception.canarysting.io/v1alpha1
   kind: DeceptionPolicy
   metadata:
     name: sample-decoys
     namespace: {{ .Release.Namespace }}
   spec:
     selector:
       labelSelector:
         matchLabels:
           app.kubernetes.io/name: your-app
     decoys:
       - type: fake_secret
         count: 2
       - type: planted_credential
         count: 1
   EOF
   kubectl -n {{ .Release.Namespace }} get deceptionpolicies
   # The "Accepted" printer column should read True once reconciled.
   # NOTE (honesty): the M1 operator VALIDATES policies and reports status only.
   # It plants NO decoys yet (SeededCount stays 0) — seeding is wired in M2.

    separate spike). Until then the datapath observes/attaches on the node but
    no L7 touches reach the adapter. See deploy/helm/README.md.
