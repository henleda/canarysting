# CanarySting Development Plan

This is the source of truth for development sequence, current work, dependencies, validation, blockers, and completion evidence. Allowed status values are `TODO`, `IN_PROGRESS`, `BLOCKED`, and `DONE`. Normally only one task is `IN_PROGRESS`. A task is `DONE` only after every acceptance criterion and its declared validation tier pass; partial code is not completion.

Validation tiers:

- **Tier A — Local:** documentation, pure Go, static analysis, generated code, serialization, and non-kernel refactoring. Typical gates are formatting, vet, focused/race tests, build, generated drift checks, and frontend lint/build when relevant.
- **Tier B — Local plus DGX integration:** eBPF, socket cookies, cgroups, kernel enforcement, Cilium, ARM64, Envoy-to-kernel attribution, DGX scripts, and low-level networking. Tier A plus the relevant DGX proof and cleanup are required.
- **Tier C — Local plus DGX Kubernetes end-to-end:** identity, Kubernetes ingestion/operator/manifests/CRDs, reconciliation, workload scope, policy ingestion, Kubernetes graph construction, and complete request-to-verdict/enforcement behavior. Tier A, relevant Tier B primitives, and DGX K3s end-to-end validation are required.

Each row below contains all mandatory task fields. `Pending` completion evidence means the task cannot be marked `DONE`.
